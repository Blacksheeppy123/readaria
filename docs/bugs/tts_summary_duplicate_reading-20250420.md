# TTS重复朗读文章开头（摘要混入正文）

## 问题描述

使用test-user账户播放"不懂经"最新文章时，TTS语音一开始似乎读了一遍文章的开头几句，然后又开始读了一遍。

**用户操作步骤**：
1. 登录test-user账户
2. 找到"不懂经"的最新文章
3. 点击播放TTS语音

**实际表现**：文章开头几句被朗读了两次
**预期表现**：文章内容只应被朗读一次

**用户猜测**：可能是因为摘要使用了文章开头几句作为内容，导致摘要和正文开头重复。由于目前摘要区分语言，建议将摘要从TTS语音中去掉。

## 原因定位

- [x] 问题定位

### 根本原因

TTS文本构建函数将 **标题 + 摘要 + 正文** 拼接在一起生成语音文本。然而摘要内容往往来源于正文开头几句：

1. **AI生成摘要**：基于正文内容提炼，通常包含开头段落的核心观点
2. **Fallback摘要** (`backend/nlp/processor.py:139-149`)：当AI摘要失败时，直接从正文中提取第一句长度≥20字符的句子作为摘要

这导致TTS播放时出现结构：
- 标题
- 摘要（=正文开头几句）
- 正文（再次从开头几句开始）

### 相关代码位置

- **`backend/api/main.py:2073-2078`** — `_build_article_tts_text()` 播放时构建TTS文本
- **`backend/storage/database.py:948-953`** — TTS预生成缓存时构建文本（与播放逻辑需保持一致）
- **`backend/nlp/processor.py:139-149`** — `_fallback_summary()` 从正文提取首句作为摘要

## 修复方案

从TTS文本中移除摘要，只保留 **标题 + 正文**。理由：
1. 摘要和正文开头高度重叠，造成重复朗读
2. 摘要区分语言，用户选择语音语言时可能与摘要语言不一致
3. TTS的目标是朗读完整文章内容，摘要并非必要
